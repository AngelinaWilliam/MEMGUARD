# Pawn profiling with MemGuard X

## Why the report showed "Top script: (no samples recorded)"

Reproduced with the unmodified 0.1.0 component and the stock `gungame` gamemode: the "script" table is fed **only** by `MemGuard_ProfileBegin/End` (or `MemGuard_ZoneBegin`) calls. A gamemode that never calls them produces no samples. Nothing in 0.1.0 measured Pawn functions on its own; native calls were (and still are) the only automatic measurement. 0.2.0 adds real per-function profiling, described below. The report now explains empty tables instead of only printing "(no samples recorded)".

## Three levels

| level | what you write | what is measured | report table / `top` kind |
|---|---|---|---|
| natives | nothing | every native call (inclusive time) | `native` |
| functions | `MEMGUARD_FUNC("Name");` as the first line of a function, or nothing if you use `memguard_instrument` | every call of the function: calls, total, self, avg, max, slow calls | `function` |
| sections | `MemGuard_ProfileBegin/End` | any part of a function | `script` |

Self time of a function excludes the natives and other profiled functions it calls, so `memguard top self 15 function` lists where the script itself spends time.

## How function profiling works

```pawn
#define MEMGUARD_FUNC(%0); static __mgx_zone = -1; new MGFunc:__mgx_frame = MGFunc:MemGuard_FuncEnter(__mgx_zone, %0);

stock operator~(const MGFunc:frames[], count)
{
    for (new i = 0; i < count; ++i)
        if (_:frames[i] > 0) MemGuard_FuncLeave(_:frames[i]);
}
```

- `MemGuard_FuncEnter` opens a profiler frame and returns a handle (frame serial). The zone name is read from the string only once per script load; afterwards the per-function `static` holds the zone id.
- Pawn calls the destructor `operator~` of a tagged local whenever control leaves its scope: at **every `return`** and at the end of the function. So the frame closes exactly when the function returns, and the return statement and its value are not modified in any way.
- `MemGuard_FuncLeave(handle)` closes only the frame with that handle. A stale handle (for example after an aborted callback) can never close a different frame.

Verified with the open.mp compiler 3.10.11 and server 1.5.8 (see VERIFICATION.md): cell, `Float:`, `bool:` and string/array return values, reference parameters, variadic functions (`numargs/getarg`), returns inside loops and `switch` cases, functions without `return`, recursion (Fib(10) = exactly 177 recorded calls), nested calls, publics called by the server, by timers and by `CallLocalFunction`. Output of the test gamemode is identical with and without instrumentation.

### Limits (measured or by design)

- **Cost**: about 0.55 us per profiled call in the test environment (100 000 calls of a trivial function: 56-63 ms instrumented vs 1-2 ms not). Part of that cost lands inside the measured time, so functions that take well under a microsecond show inflated times. Exclude tiny hot helpers (`--exclude`) and profile callbacks/commands first (`--only-public`).
- **Recursion**: self time is exact; total (inclusive) time of a recursive function counts nested recursive calls again (standard for inclusive profilers).
- **Runtime errors / `exit`**: the destructor does not run when the AMX aborts. The open frames are discarded at the next server tick (counted as `abandoned` in `memguard status`); the aborted call is not recorded and later measurements stay correct (verified).
- Sections opened with `MemGuard_ProfileBegin` must end in the same callback execution; still-open sections are discarded at the next tick (new in 0.2.0).
- Functions generated by macros the tool cannot see (e.g. YSI `timer Name[100]()`, `ptask`) are reported as skipped or not found; put `MEMGUARD_FUNC` in them by hand. Headers written through macros that end in a normal `name(...) {` (zcmd `CMD:x(...)`, y_hooks `hook OnX(...)`) are recognised.
- Functions containing `#emit`/`__emit` are skipped by default because hand-written assembly may address locals by fixed frame offsets, and MEMGUARD_FUNC adds two locals. Use `--allow-emit` only if you know the assembly uses symbolic names.

## Automatic instrumentation: `memguard_instrument`

A host tool (built with the project, Windows or Linux) that writes an **instrumented copy** of your sources; originals are never modified.

```
memguard_instrument --out <dir> [--root <dir>] [options] <file-or-directory>...

  --exclude <name>   skip matching functions (wildcards *), repeatable
  --only <name>      instrument only matching functions, repeatable
  --only-public      only public functions (callbacks, timers, commands)
  --prefix <text>    prefix zone names, e.g. gm:  (useful with several scripts)
  --allow-emit       also instrument functions containing #emit / __emit
  --dry-run          print what would be done
```

What it does for each `.pwn/.p/.inc` file:

- finds function **definitions** at file scope (skips `native`, `forward`, `enum`, array initialisers, `operator` functions, `#define` bodies, comments and strings, including raw `\"..."` and packed `!"..."` strings);
- inserts `MEMGUARD_FUNC("<name>");` in front of the first statement of the body, **on the same line**, so compiler messages keep the original line numbers (if the body starts with a preprocessor line, it is inserted right after `{` instead, so it can never end up inside an `#if` branch);
- skips functions that already contain `MEMGUARD_FUNC` (re-running is harmless), MemGuard X's own functions and `memguard.inc`;
- refuses to instrument a file with unbalanced braces/parentheses or unterminated strings/comments and reports the line instead of guessing;
- writes `memguard_instrument.txt` listing every function as `[profiled]` or `[skipped] (reason)`.

Typical build (Windows, qawno layout):

```bat
memguard_instrument --out build\instrumented --exclude "Iter_*" gamemodes\mygm.pwn gamemodes\modules
qawno\pawncc.exe build\instrumented\mygm.pwn -obuild\mygm.amx -ibuild\instrumented -iqawno\include -d1 -O1 -;+ -(+
copy build\mygm.amx gamemodes\
```

Only instrument your own sources (the gamemode folder). Library includes from `qawno/include` stay as they are; they are found through the normal `-i` path.

Zone names are the function names (`CMD:help`, `hook OnPlayerConnect` and state functions `Walk<moving>` keep their prefix/suffix). Several scripts with the same function name share one zone unless you use `--prefix`.

## Pawn API reference (verified against `src/component/pawn_bridge.cpp`)

The unit test `include_api_matches_registered_natives` fails if the include and the component ever disagree on names or parameter counts.

| native | returns |
|---|---|
| `MemGuard_FuncEnter(&cache, const name[])` | frame handle > 0, or 0 (profiling disabled / depth limit 256) - used by `MEMGUARD_FUNC` |
| `MemGuard_FuncLeave(frame)` | 1 if the frame was open and is now closed, else 0 - used by `operator~` |
| `MemGuard_ProfileBegin(const name[])` | zone id >= 0, or -1 |
| `MemGuard_ProfileEnd(zone)` | 1 closed, 0 not open |
| `MemGuard_ZoneId(const name[])` | zone id or -1 |
| `MemGuard_ZoneBegin(zone)` | 1 started, 0 failed |
| `MemGuard_GetZoneCalls(const name[])` | recorded calls, 0 if unknown, -1 invalid argument |
| `MemGuard_GetZoneStats(const name[], &calls, &total_us, &self_us, &max_us)` | 1 found (outputs set), 0 unknown (outputs 0) |
| `MemGuard_TrackAlloc(const category[], id, size = 0)` | `MG_ALLOC_TRACKED` 1, `MG_ALLOC_DUPLICATE` 2, `MG_ALLOC_IGNORED` 0 |
| `MemGuard_TrackFree(const category[], id)` | `MG_FREE_RELEASED` 1, `MG_FREE_UNKNOWN` -1, `MG_FREE_DOUBLE` -2, `MG_FREE_IGNORED` 0 |
| `MemGuard_GetActiveCount(const category[])` | active entries, 0 unknown category, -1 invalid argument |
| `MemGuard_Snapshot()` | snapshot sequence number |
| `MemGuard_WriteReport()` | 1 written, 0 failed |
| `MemGuard_GetVersion()` | `(major << 16) | (minor << 8) | patch` (0x000200 for 0.2.0) |

## Without the component

open.mp refuses to run a script whose natives are not registered (verified: `Function not registered: MemGuard_...` followed by `File or function is not found`). There is no way for Pawn code to test for a native at run time without referencing it, so graceful degradation is a **compile-time** switch: compile with `MEMGUARD_DISABLE` defined (`pawncc ... MEMGUARD_DISABLE=1`, or `#define MEMGUARD_DISABLE` before the include). Every API call then becomes a stub returning 0 / -1 / `MG_*_IGNORED`, and `MEMGUARD_FUNC` expands to an empty statement. Verified: an instrumented script compiled this way runs on a server without MemGuard X and prints the same output as the original.
